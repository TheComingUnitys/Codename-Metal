# Codename Engine - Metal Backend (macOS)

**English** | [中文](docs/zh-CN/README.md)

**Repository**: https://github.com/TheComingUnitys/Codename-Metal  
**Documentation languages**: repository-authored docs are English by default and each links to
its Chinese translation under [docs/zh-CN](docs/zh-CN/README.md); upstream engine docs stay in
English with a Chinese summary index at [docs/zh-CN/upstream/README.md](docs/zh-CN/upstream/README.md).

**Codename Engine 1.0.1** plus a native **Metal / bgfx** rendering backend for macOS.
The game is a Friday Night Funkin' engine; this repository adds the port that makes it run
on Metal instead of OpenGL, AOT-compiles every GLSL shader to Metal Shading Language, and
documents how it was built and debugged.

> This project = upstream [Codename Engine 1.0.1](https://github.com/CodenameCrew/CodenameEngine)
> plus a from-scratch **Metal (bgfx) renderer**. Goal: render everything through Metal on
> macOS (no GL context) while keeping the original OpenGL path compatible.

> the Lime/OpenFL/HaxeFlixel ecosystem and bgfx remain under their original licenses

## 1. Features

- **Metal rendering**: every 2D draw goes through the `lime_gl_*` GL-shaped compatibility
  layer into bgfx's Metal backend. No GL context and no GL swap chain exist in the process.
- **Shader AOT**: GLSL is translated to Metal Shading Language at build time and precompiled
  into `.metallib` files (**116 cached shader stages**, **114 / 116** ship a prebuilt library;
  zero runtime GLSL translation for the engine corpus).
- **Two paths**: the Lime `lime_gl_*` CFFI compatibility layer plus the faster native
  `cne_metal_*` path (enabled by default).
- **Diagnosable**: 70 `CNE_METAL_*` environment switches (`CNE_METAL_PROFILE`,
  `CNE_METAL_DRAWPROBE`, `CNE_METAL_COVERAGE`, `CNE_METAL_HITCH`, ... - see section 8).
- **Verified on hardware**: main menu, warning screen, intro cutscene, freeplay, Dusttale
  battles, Winter Horrorland, pause menu and third-party shader effects.

## 5. Dependencies

### 5.1 System

- macOS 11+ (Apple Silicon or Intel; scripts default to `osx-arm64`)
- Xcode **Command Line Tools** (clang and the metal toolchain: `xcode-select --install`)
- Python 3 (AOT / metallib generation)
- `git`, `make`, `pkg-config`

### 5.2 Haxe toolchain

```sh
haxelib install hxcpp 4.3.2

cd CodenameEngine-1.0.1
haxelib install flixel flixel-addons flxanimate format hscript-improved markdown away3d
haxelib install hxvlc hxdiscord_rpc nape-haxe4 funkin-modchart hxcpp-debug-server   # optional
```

> If you use the in-project local haxelib store (`.haxelib/`, gitignored), add it to the
> haxelib search path or install the libraries into the default store.

### 5.3 Lime 8.3.2 (dev checkout) + patches

```sh
git clone --depth 1 --branch 8.3.2 https://github.com/openfl/lime.git ~/haxelib-dev/lime-832
haxelib dev lime ~/haxelib-dev/lime-832
```

Patches are applied automatically by `metal/scripts/apply.sh` (section 6); no manual editing.
They are also exported as an upstreamable, verified patch:
`metal/patches/lime-metal.patch` (SHA-256 + `export-lime-patches.sh --verify`, see
[docs/LIME-PATCHES.md](docs/LIME-PATCHES.md)).

### 5.4 bgfx (Metal static libraries)

> bgfx upstream: **https://github.com/bkaradzic/bgfx** (the static libraries come from its
> Metal renderer).

```sh
git clone --depth 1 https://github.com/bkaradzic/bgfx.git ../bgfx-master
cd CodenameEngine-1.0.1
./metal/scripts/build-bgfx.sh
# output: ~/bgfx-build/bgfx/.build/osx-arm64/bin/libbgfxRelease.a (+ bx/bimg)
```

## 6. Build

All commands run from `CodenameEngine-1.0.1/`.

### 6.1 First full build

```sh
cd CodenameEngine-1.0.1

export MACOSX_DEPLOYMENT_TARGET=11.0
# (1) install the backend into the Lime checkout, generate the AOT cache, rebuild the ndll
./metal/scripts/apply.sh --lime "$HOME/haxelib-dev/lime-832" --build

# (2) compile the game (Haxe -> cpp) into export/release/macos/bin/CodenameEngine.app
haxelib run lime build mac

# (3) install the cpp ndll back into the app (step 2 ships the neko bootstrap)
./metal/scripts/apply.sh --lime "$HOME/haxelib-dev/lime-832" --build --deploy
```

Run it:

```sh
./export/release/macos/bin/CodenameEngine.app/Contents/MacOS/CodenameEngine
```

### 6.2 Incremental builds

| Changed | Re-run |
| --- | --- |
| `metal/native/*` (C++) | `./metal/scripts/apply.sh --lime "$HOME/haxelib-dev/lime-832" --build --deploy` |
| `metal/haxe/*` or `source/*` (Haxe) | `haxelib run lime build mac`, then `apply.sh ... --build --deploy` |
| game assets only | `haxelib run lime build mac` (or edit the app bundle directly) |

### 6.3 AOT shader cache

`apply.sh` runs `metal/scripts/gen_shader_aot.py` before building:

- enumerates every GLSL source (OpenFL/Flixel/CNE/external) -> MSL -> `.metallib`;
- writes `ShaderAotCache.hx` (~2.0 MB, 114 prebuilt libraries);
- after changing the translator or a shader, force a rebuild:

```sh
rm -f metal/haxe/lime/graphics/metal/ShaderAotCache.hx
python3 metal/scripts/gen_shader_aot.py
rm -rf export/release/macos/obj/src/lime/graphics/metal/   # hxcpp does not track generated deps
```

### 6.4 Universal (arm64 + x86_64) and DMG

```sh
./metal/scripts/make-universal.sh --check            # toolchain/bgfx preflight only
./metal/scripts/make-universal.sh --dry-run --dmg    # print the full plan
./metal/scripts/make-universal.sh --dmg ~/Downloads/CodenameEngine-Metal-1.0.1.dmg
./metal/scripts/make-universal.sh --verify export/release/macos/bin/CodenameEngine.app
```

- `lime build mac` only emits the host architecture; the script builds the x86_64
  executable/ndll separately (`HXCPP_M64` / `-DCNE_X64`) and merges with `lipo`;
- DMG packaging copies the app, strips bundled third-party mods by default, re-signs
  (ad-hoc) and runs `hdiutil create/verify` + SHA-256;
- options: `--reuse`, `--keep-mods`, `--no-sign`, `--out DIR`; release steps in
  [docs/RELEASE.md](docs/RELEASE.md).

## 8. Diagnostics (environment variables)

> Prefer the unified entry point `metal/scripts/diag.sh` (`--list` shows categories).
> Full details, log formats, frame capture/replay and pixel regression:
> [docs/DIAGNOSTICS.md](docs/DIAGNOSTICS.md). Legacy variables keep working.

| Switch | Effect |
| --- | --- |
| `CNE_METAL_PROFILE=1` | every 240 frames: draws/frame, CPU front-end cost, texture uploads |
| `CNE_METAL_HITCH=1` / `CNE_METAL_HITCH_DETAIL=1` | report frames > 34 ms; DETAIL splits game/submit/present/rest |
| `CNE_METAL_DRAWPROBE=1` | per draw: program/fbo/tex/size/rt/m0/m5/m13 |
| `CNE_METAL_SHOT_RAW=<frame>:<path>[,<frame>:<path>...]` | write raw BGRA frame + `.txt` metadata (multi-frame) |
| `CNE_METAL_UVLOG=1` | screen composite flip decision |
| `CNE_METAL_FBOLOG=1` | framebuffer create/invalidate log |
| `CNE_METAL_COVERAGE=1` (+`_OUT=<file>`) | per-`lime_gl_*` call counts |
| `CNE_METAL_AOT_AUDIT=1` / `CNE_METAL_MTL_AUDIT=1` | AOT hit/miss, shader load source and compile time |
| `CNE_METAL_STATE_RESET=1` | rebuild swap chain/FBOs when entering new states (debug only) |
| `CNE_METAL_RT_UVFLIP`, `CNE_METAL_FBO_FLIP`, ... | flip/sampling experiments (defaults are the verified values) |

## 9. Backend design notes

1. **GL-shaped compatibility layer**: OpenFL/Lime still call `lime_gl_*`; the backend maps
   state, VAOs, constant attributes, FBO attachments and texture formats onto bgfx and turns
   every draw into `bgfx::submit`.
2. **Native fast path**: `cne_metal_*` skips CFFI and GL enum translation (used by default
   after the Lime patches).
3. **AOT shaders**: build-time GLSL->MSL plus `.metallib`; runtime only does a hash lookup,
   avoiding first-use shader compilation stalls.
4. **Orientation/mirroring**: offscreen targets mirror the matrix only when required; the
   screen composite flips V based on the target's actual render orientation (determined with
   `CNE_METAL_DRAWPROBE/UVLOG`; details in `docs/zh-CN/metal/README.md`).
5. **FBO cache**: bgfx framebuffers are cached per (GL FBO, attachment texture) to support GL
   ping-pong semantics; re-uploading a texture invalidates the dependent FBOs.
6. **Performance**: O(1) vertex/index buffer caching keyed by revision; same-size texture
   re-uploads use `updateTexture2D`; hot-path containers are reused.

## 11. Known limitations / roadmap

[docs/METAL-TODO.md](docs/METAL-TODO.md) only lists open items now:

- architecture: OpenFL still goes through the GL-shaped API; Metal-native `Context3D` and
  dropping bgfx are future work (plans and A/B prototype in
  `docs/zh-CN/metal/audit/openfl-native.md`, `metal/tools/native_replay/`);
- **2** shader stages have no prebuilt `.metallib` (external shader source issues; coverage 114/116);
- `DisplayObject.mask` is wired on the engine side but needs runtime verification;
  `readPixels` (screenshots/readback) is still unimplemented;
- 3D / Stage3D capabilities are not implemented;
- GL states bgfx cannot express (`blendColor`, `depthRange`, `polygonOffset`, `lineWidth>1`,
  MSAA, nested-mask stencil write-mask, ...) are recorded and warned about once; the decision
  is not to implement them (see `docs/DIAGNOSTICS.md` section 4.1).

## 12. Troubleshooting

| Symptom | Fix |
| --- | --- |
| `Failed to create Fragment shader` | shader not in the AOT cache; check `CNE_METAL_AOT_AUDIT` and `CNE_METAL_AOT_RUNTIME_TRANSLATE` |
| black screen / wrong orientation after a build | unset experimental `CNE_METAL_*` switches; clear `export/.../obj` and rebuild |
| Haxe changes not taking effect | re-run `haxelib run lime build mac` (`apply.sh --build` only updates the C++ ndll) |
| app quits immediately | make sure `lime.ndll` is the cpp build: `apply.sh ... --deploy` |
| one-off stall entering a state | `CNE_METAL_PROFILE=1 CNE_METAL_HITCH=1`; usually asset creation/GC |
